The one structural decision

Sidebar and content pane. No top bar.

The dashboard being replaced has a 64px sticky top bar carrying a hamburger, a logo, a breadcrumb, a theme toggle, a bell and a settings gear. Removing it means five things need somewhere to live — this is where each one went, and why. Nothing is homeless.

Where each top-bar concern went

Was in the top barNow livesWhy there
Search Sidebar zone 2 → ⌘K palette over the pane An upgrade, not a relocation: the palette does search and navigation, so it absorbs the nav's job too.
Breadcrumb Content header, row 1 It describes the pane, so it belongs to the pane. It also inherits the house mono eyebrow, and the tab state (?tab=) is already its last crumb.
Notifications Sidebar zone 4 → right-side sheet A sheet, not a popover — that reuses BaseListSheet, so notifications need no new overlay primitive.
Theme toggle Sidebar zone 4 Set once, rarely touched. It belongs with the other chrome, not beside page actions.
User menu Sidebar zone 5 → popover opening upward Bottom-pinned, which is where the existing sidebar already puts it. Nothing above to drop from.
Settings gear Deleted It was non-functional, and Settings is already nav item 8.

The risk, named

{{icon:triangle-alert:13}} What could go wrong
With no persistent bar, a page's primary action can scroll away and leave the user with no obvious next move — the classic failure of this layout.
{{icon:check:13}} What prevents it
The content header is sticky top-0 and keeps the primary action in row 1. It gains its bottom border only once scrolled, so it is flat and quiet at rest.

Mobile. Under 1024px the sidebar becomes an overlay drawer and the content header grows a hamburger at the left of row 1, with the breadcrumb collapsing to its last crumb. The sticky content header is the mobile top bar — a separate global bar never enters the DOM at any breakpoint.
