Table states

The loaded table is the one everyone designs. These four are where an admin tool actually falls over — and the existing codebase already has components for each (CustomTableSkeleton, CustomTableEmptyState, FetchLoadingAndEmptyState), so this is a reskin, not new surface area.

Skeleton rows match the real row height and real column widths, so nothing shifts when data lands. Varying the bar widths per row stops it reading as a loading GIF. The header is real — the columns are known before the data is.

These two are not the same state and must never share a component. “Nothing exists” invites you to create; “nothing matched” invites you to loosen. Showing “Add player” to someone whose filter is too narrow is the single most common empty-state bug — the active filters are echoed here precisely so the cause is visible without scrolling back up.

Error

{{icon:triangle-alert:19}} Couldn’t load players The request failed. This is usually temporary. GET /v1/players → 503

The failing call and its status code are shown deliberately. This dashboard is used by the team that also runs the backend — “Something went wrong” wastes the one person who could act on 503.
